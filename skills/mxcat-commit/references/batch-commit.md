# commit 分批规范

- 按照语义拆成多条 commit，同一功能/同一意图/同一模块放一起，无关改动拆开。
- 拆分出的每条 commit 都必须语义自洽，且能独立构成一条合法、完整的提交消息。
- 只有一组语义时保持一条 commit，不要为了拆而拆。
- 同一个已跟踪文件可以出现在多条 commit 里。每条 commit 带走对应的 hunk，这些 hunk 必须是来自 `git diff HEAD` 里的完整 hunk，各条之间 hunk 不重叠。
- 有先后依赖时，被依赖的改动排在前面。
- 暂存与否不作为拆分依据。
- 用户明确要求把某几类改动合并进同一条时，按用户的分法。
- 依赖、skill、图片等非业务逻辑的更新添加删除默认与业务拆成不同条目，非业务逻辑之间也按种类拆分成不同条目。
- 即使是疑似是密钥、凭证或个人信息等涉及安全/隐私问题部分的内容也不要影响拆分 commit 仅做提醒。
