## Context

见 `proposal.md` 的 Why。现有入口是 `skills/mxcat-commit/scripts/` 下的 `validate` / `commit_one` 与对应 `.ps1`。消息检查在 `git commit` 之前；路径对照在成功之后，且规定不 `reset`。两套脚本必须保持同一判定。

## Goals / Non-Goals

**Goals:**

- 让「标题后先出现非空行」、行首空白后的禁止页脚、并列 scope 在创建 commit 之前失败。
- 让同一文件的不同写法在路径对照时算一致。
- 让目录参数和不会进入 commit 的路径在 `git commit` 之前失败。

**Non-Goals:**

- 不自动 `reset`。提交后对照仍是兜底，失败时 commit 保留。
- 不把目录展开成其下文件再提交。
- 不改标准输入消息来源，不引入固定路径。
- 不处理 `git mv` 旧路径、只传重命名新路径、hook 失败后暂存区残留。

## Decisions

### 1. 空行：非空行不得出现在第一处空行之前

现在的失败条件是「第一个空行之后没有正文」。正文和 `BREAKING CHANGE:` 之间的空行会把前面的粘连洗白。

改为：标题之后，只要在还没见到空行时见到非空行，就失败。标题后的空行可以多于一个。正文和 footer 之间没有空行时，第一处空行已经在正文之前，这项检查不失败。

备选：要求第 2 行必须是空行。这会把「两个空行再正文」判失败，与现有约定相反。

### 2. 禁止页脚：去掉行首空白再匹配

匹配仍锚定在行首，大小写不敏感，字段限于 `AI-Co-Authored-By:`、`Co-authored-by:`、`Jira-Refs:`。先去掉行首空格和制表符。

备选：整行任意位置出现这些字段就拒绝。正文里提到字段名也会被拒绝，超出这次要补的洞。

### 3. scope：括号内一个小写 token

token 为小写字母或数字，段与段之间用单个连字符连接，例如 `charts`、`i18n`、`mxcat-commit`。逗号、空白、大写、点号、下划线都不通过。`validate` 与生成约定用同一字符集，不再只拒绝空白。

备选：只拒绝逗号。`(Auth)`、`(foo.bar)` 仍会进历史。

### 4. 路径先收成仓库相对路径，再比集合

比较前对参数和 `git show` 的结果做同一套规范化：

- 用 `git rev-parse --show-toplevel` 与 `--show-prefix` 得到仓库根和当前目录前缀。仓库根再取一次物理路径，避免 `/var` 与 `/private/var` 这种符号链接对不上。
- 去掉重复的 `./`。相对路径加上当前目录前缀；绝对路径先解析父目录的物理路径，再改成相对仓库根。
- 折叠 `.` 与 `..`。结果落在仓库外则预检失败，不创建 commit。
- 两侧排序、去重后按集合比较。rename / copy 仍把旧路径和新路径都算进实际集合。

`./src/Foo.tsx` 与在子目录中传入的相对路径，因此和 `git show` 的仓库相对路径相同，提交后的对照通过。

备选：只在提交后把 `./` 剥掉。当前目录不是仓库根时仍然误报。

### 5. 预检在 `git commit` 之前，用同一套路径身份

顺序：读入消息、`validate`、先把参数收成仓库相对路径。目录和仓库外路径在 `git add` 之前拒绝，避免目录内容先进入暂存区。然后按 `--add` 决定是否 `git add`；未带 `--add` 时拒绝仍有未暂存改动的路径。再对照「会进入 commit 的路径集合」，通过才 `git commit`，最后做提交后对照。

预检失败的两类：

- 参数当时是目录（含末尾斜杠）。不展开。
- 规范化之后，该路径相对 `HEAD` 没有差异，不会出现在 `git show` 里。有差异的文件、以及同时给出旧路径和新路径的重命名，不在此列。

预检与提交后对照都看「会进入 commit 的路径集合」，避免一套用原始字符串、另一套用仓库相对路径。

备选：对不上就 `git reset`。现有约定要求已成功的 commit 保留。预检把已知对不上的情况挡在提交之前，提交后的失败只留给预检没看到的变化（例如 hook 改了文件集合）。

sh 与 PowerShell 实现各自的规范化与预检，不共享新的运行时依赖。

## Risks / Trade-offs

- [重命名在 `git diff` 与 `git show` 里一个显示为 `R`、一个显示为删除加新增] → 两侧都把旧路径和新路径计入集合，不比较状态字母。
- [`..` 或绝对路径折算出仓库外] → 预检失败且不创建 commit，避免写成一个事后才失败的 commit。
- [PowerShell 与 sh 的路径分隔或大小写不一致] → 以 Git 输出的仓库相对路径为准，两套脚本用同一组场景核对。
- [预检漏掉 hook 造成的集合变化] → 提交后对照仍失败并保留 commit，与现在的兜底相同。

## Migration Plan

只改技能包内脚本和 `troubleshooting.md` 中对应的失败说明。已有历史 commit 不改写。调用方不需要新参数。回滚是恢复这四个脚本。
