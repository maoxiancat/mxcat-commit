## Context

技能仍是文档约束 agent。确认表写在 `SKILL.md` 预览门禁，以及 `references/single-commit.md` / `references/batch-commit.md` 第 4 步；固定收尾三处复述同一句。见 `proposal.md` 的 Why。不引入解析器或 plan JSON。

## Goals / Non-Goals

**Goals:**

- 预览后的确认写成「独立的「提交」」判定，配少量正反例子，而不是加长白名单。
- 第 4 步表补上子集当场做、改字+提交同句、拆合仍重出；三处收尾换成短句。
- 编号继续认 `## commit N`。

**Non-Goals:**

- 不恢复 `lgtm` / `就这样` / 单独的「确认」「可以」为确认词。
- 不引入执行器、词法解析器或结构化确认协议。
- 不改 `--only`、密钥提醒、回执字段结构。
- 不允许用等价句替换固定收尾。

## Decisions

### Decision: 用行为判定，不扩白名单

默认加载层写清：预览后看这句话是不是在下令做 commit。举「提交吧」「好的，提交吧」「可以提交」为是；举单独软附和与疑问句为否。「不要提交」里的「提交」不是独立的「提交」。两份 guide 第 4 步用同一张表，不要各写一套同义词。

Alternatives considered:

- 把「提交吧」「可以提交」加进白名单：名单会永远不够。
- 句子里出现「提交」就执行：会把「不要提交 commit 2」当成整单批准。

### Decision: 可以提交预览后算批准

与「好的，提交吧」同一条规则：软词加上独立的「提交」。1.1.0 把它放进否定名单，是为了废止当时的确认词表；本次按行为收回，不收回 `lgtm`。尚未出预览时「可以提交」仍只出卡。

### Decision: 点名子集当场做，只丢掉则重出

被点名的条已经在整单预览里出示过，同轮提交，不必再出子集卡。没点名的当丢掉，文件留工作区，回执走既有「工作区仍有未提交变更」。只有丢掉、没有批准剩余时，仍重出再等。认不清「第二条」就问。

Alternatives considered:

- 子集也先重出再等一句「提交」：填不上这张缺口。
- 子集提交后再自动重出剩余预览：用户没要继续确认。

### Decision: 改字可同句提交；拆合必须先重出

标题 / emoji / scope / 正文是用户刚口述的新稿，同句独立的「提交」即可做。拆开、合并、合为一条会生成用户没看过的新标题或新分组，即使带「提交」也先出新卡。

### Decision: 收尾缩短仍逐字，教学放进确认表

三处原文改为：尚未提交。回复「提交」或「提交并 push」。子集与改稿不写进收尾，避免句子再次变长、模型改字。

## Risks / Trade-offs

- [Risk] 「独立的「提交」」仍靠文档，agent 可能把「可以提交吗」当成批准，或把「好的，提交吧」继续卡住。  
  Mitigation: SKILL 与第 4 步表正反例子对着写；否定名单保留软附和与疑问句。

- [Risk] 「改标题，提交吧」按新稿直接提交，用户没看到更新后的卡片。  
  Mitigation: 只覆盖字面改动；拆合仍重出。

- [Risk] 「只提交第二条」猜错编号。  
  Mitigation: 对不上 `## commit N` 就问，不要猜。

- [Trade-off] 「可以提交」预览后重新生效，与 1.1.0 changelog 不完全一致。  
  Mitigation: 本次 changelog 写明收回的是这一句，不是 `lgtm`。

## Migration Plan

1. 先改 `SKILL.md` 预览门禁：独立「提交」、子集、改字同句、短收尾。
2. 再改 single / batch 第 4 步表与预览模板收尾，两边同字。
3. troubleshooting 里若出现旧收尾或旧确认词，改成新原文与新判定。
4. CHANGELOG 记录确认判定、子集提交与收尾缩短。
5. 回滚即还原上述 markdown。
